Data & Cohort

1 Data source and type

All data originate from shotgun metagenomic sequencing of stool samples, accessed through the curatedMetagenomicData Bioconductor package (package version 3.12.0, confirmed via sessionInfo() inside the pinned analysis container) (Pasolli et al. 2017). Two feature types are pulled per cohort, each from a separately pinned ExperimentHub snapshot date (config/config.yaml):

Feature type curatedMetagenomicData resource What it measures
Species relative_abundance Relative abundance of taxonomically classified microbial species (MetaPhlAn-derived)
Pathway pathway_abundance Relative abundance of MetaCyc functional pathways (HUMAnN-derived)

Snapshot dates: 2021-10-14 for HMP_2019_ibdmdb, HallAB_2017, and IjazUZ_2017; 2021-03-31 for NielsenHB_2014 — pinned explicitly so the same underlying data version is pulled on every re-run, validated with a dry run before each pull.

ImportantKnown reproducibility caveat

Unlike relative_abundance/pathway_abundance, curatedMetagenomicData’s sampleMetadata table (subject-level clinical/demographic metadata) is not independently version-pinned — it is baked into the installed package version itself. A documented consequence: this rebuild finds 0/141 NielsenHB_2014 samples with non-missing age, versus an original exploratory run’s age-adjusted Tier 2 subset of n=314 across three cohorts (this rebuild: n=173). This is package-version drift in the metadata table, not a pipeline bug — downstream scripts log the actual n observed rather than asserting the original number.

2 Cohort composition

Four cohorts were selected (config/config.yaml: cohorts.selected_studies), restricted to stool samples, with NielsenHB_2014 additionally restricted to its Spanish (ESP) subset only (nielsen_country_restriction: "ESP") to avoid mixing populations within that single study. Where a subject was sampled at multiple time points, only the earliest baseline sample per subject was retained (scripts/r/01_cohort_selection.R) — so every count below is a patient/subject count, not a longitudinal sample count.

This single-subject discrepancy is a real artifact of the pathway abundance filtering/deduplication step and is called out explicitly rather than silently reconciled — see the feature filtering section below for where it occurs.

3 Feature filtering

Both feature types pass through the same two-stage filter — (1) an abundance/prevalence threshold, and (2) a majority-cohort-prevalence rule requiring the feature to be reasonably prevalent within most cohorts individually, not just pooled — followed by correlation-based deduplication (Spearman r > 0.9999999 flagged; exact duplicates collapsed via cluster keep-first-drop-rest, near-duplicates additively collapsed).

Thresholds: species_filter.abund_threshold=0.01, prev_threshold=0.10; pathway_filter.abund_threshold=0.0001, prev_threshold=0.10; both use majority_cohort_prevalence=0.05, majority_cohort_min_n=3 (config.yaml).

4 Pipeline workflow

The pipeline is orchestrated with Snakemake, split into two fully parallel tracks (species, pathway) that share identical statistical logic, plus a downstream Python machine-learning stage that consumes both. Execution runs on SLURM (IU Quartz HPC), with R analysis inside an Apptainer container (bioconductor/bioconductor_docker:RELEASE_3_19, R 4.4.1) and Python ML inside a separate conda environment, tracked end-to-end with MLflow.

Every rule maps to one numbered R script (scripts/r/01–21) or Python script (scripts/python/02–07); the numbering above matches the actual filenames in the repository so any step can be traced directly back to its source.
